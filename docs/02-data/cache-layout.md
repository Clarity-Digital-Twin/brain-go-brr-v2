# Cache Layout and Manifests

## Dataset Strategy

- **Training** uses `BalancedSeizureDataset` with the cache manifest to oversample seizures (≈8 % → 30 %).
  - Requires `train/manifest.json` (auto-generated by `scan-cache`).
- **Validation** uses `ValidationDataset` with the natural seizure distribution (7.7% seizure ratio).
  - Requires `dev/manifest.json` for instant loading (99.6% faster than NPZ scan).
  - Falls back to `EEGWindowDataset` if manifest is missing (not recommended).
- This split preserves the real-world distribution for evaluation while keeping batches seizure-rich during training.

## Locations

| Environment | Path                                    | Notes |
|-------------|-----------------------------------------|-------|
| Local       | `cache/tusz_mmap/{train,dev}`           | Memory-mapped cache on local SSD/NVMe |
| Modal       | `/results/cache/tusz_mmap/{train,dev}`  | Persistent SSD volume (populated from S3) |
| S3 backup   | `s3://brain-go-brr-eeg-data-20250919/cache/tusz_mmap/` | Populate Modal from here |

## Memory-Mapped File Layout

Each EDF recording produces two uncompressed `.npy` files (cache is strictly read-only; datasets raise `FileNotFoundError` if a stem is missing so you know to repopulate):

| File                    | Shape                       | Dtype    | Description |
|-------------------------|-----------------------------|----------|-------------|
| `<stem>_data.npy`       | `(n_windows, 19, 15360)`    | `float32` | EEG windows |
| `<stem>_labels.npy`     | `(n_windows, 15360)` (optional) | `uint8` | Seizure masks (absent for background-only files) |

The dataset loaders call `np.load(..., mmap_mode='r')`, so the OS page cache handles memory automatically. Balanced manifests still reference the stem name; the loader resolves the matching `_data.npy/_labels.npy` pair.

## Index & Manifest Files

- `_dataset_index.json`: Generated by `scan-cache`, stores filenames and window counts for quick initialisation.
- `manifest.json`: Required for `BalancedSeizureDataset` (train split) and optional for validation.

## Building / Refreshing the Cache

```bash
# Convert NPZ cache to mmap format (one-time per split)
python scripts/convert_cache_to_mmap.py \
  --source cache/tusz/train \
  --dest cache/tusz_mmap/train
python scripts/convert_cache_to_mmap.py \
  --source cache/tusz/dev \
  --dest cache/tusz_mmap/dev

# Regenerate manifests and indices for the mmap cache
python -m src scan-cache --cache-dir cache/tusz_mmap/train
python -m src scan-cache --cache-dir cache/tusz_mmap/dev
```

## Environment Flags

- `BGB_FORCE_MANIFEST_REBUILD=1` — Force `scan-cache` to regenerate manifests on startup.
- `BGB_SMOKE_TEST=1` — Limit to three files and disable expensive sampling (used by smoke configs).
- `BGB_LIMIT_FILES=N` — Cap the number of cache files for quick tests.

## Performance Highlights (vs NPZ)

| Metric                 | NPZ cache        | NPY mmap cache    |
|------------------------|------------------|-------------------|
| RAM / worker           | 85 GB+ (OOM risk) | <1 GB (OS managed) |
| Window access time     | ~1.1 s            | ~0.01 ms          |
| Validation epoch time  | >10 min           | <2 min            |
| Worker memory sharing  | No                | Yes (page cache)  |

## Modal Workflow Recap

1. Ensure local mmap cache is complete and manifests are up to date.
2. Sync to S3: `aws s3 sync cache/tusz_mmap/...` (train and dev directories).
3. Run `modal run --detach deploy/modal/app.py --action populate-cache` to copy into `/results/cache/tusz_mmap/`.
4. Validate the volume: `modal run deploy/modal/app.py --action check-cache` (verifies train/dev counts, manifest freshness, and detecs stray NPZ files).
5. Smoke test BiMamba2 (`configs/modal/smoke_bimamba.yaml`) or FLA (`configs/modal/smoke_fla.yaml`) to verify memory usage and throughput.
6. Launch full training: BiMamba2 baseline (`configs/modal/train_bimamba.yaml`) or FLA research (`configs/modal/train_fla.yaml`).

## Recovery Tips

- To rebuild locally: `rm -rf cache/tusz_mmap && make train-local` (training will recreate the cache).
- To clean Modal cache: `modal run deploy/modal/app.py --action clean-cache` before re-populating.
- To remove stray NPZ files left by aborted runs: `modal run deploy/modal/clean_stray_npz.py --confirm`.
- To inspect Modal cache health without modifying it: `modal run deploy/modal/app.py --action check-cache`.
- Keep the old NPZ cache (`cache/tusz/`) until the migration is fully validated; switching back only requires pointing configs to the old path.

## Cost Notes

- Local disk: ~500 GB for mmap cache (≈50 GB growth vs NPZ).
- S3 storage: ≈$12/month for the mmap copy.
- S3 egress (one-time per full upload): ≈$45.
- Modal populate-cache run: ≈$1 (CPU time) — much cheaper than rebuilding from scratch on GPU.

Maintain the mmap cache to avoid costly A100 downtime and to keep validation epochs fast.
