# Bug Hunt – October&nbsp;9, 2025

Curiosity pass over the post‑config‑split repo turned up several regressions. Nothing is fixed yet; this is the audit log so we can triage in whatever order makes sense.

---

## P0 — Unit Test Still Points At Deleted Configs

- **Where**
  - `tests/unit/models/test_nan_robustness.py:312-336`
  - Relies on `configs/local/train.yaml` and `configs/modal/train.yaml`
- **What happens**  
  The test opens both YAMLs to confirm NaN‑safety parity. After the BiMamba2/FLA split those filenames disappeared, so the test now raises `FileNotFoundError` before any assertions.
- **Reproduce**
  ```bash
  python - <<'PY'
  from pathlib import Path
  Path('configs/local/train.yaml').open()
  PY
  # -> FileNotFoundError: ... 'configs/local/train.yaml'
  ```
  A full `pytest tests/unit/models/test_nan_robustness.py -k config_consistency_local_vs_modal` would fail the same way (conftest currently needs torch, but the file open happens before any model code).
- **Why it matters**  
  CI will hard fail the first time we run the NaN robustness suite; meanwhile it hides any real parity issues between the new configs.
- **Likely fix (not applied)**  
  Update the test to target `train_bimamba.yaml`/`train_fla.yaml` (or parametrize over both stacks) so the parity check points at living files.

## P0 — Modal Entrypoint Defaults Reference Removed Configs

- **Where**
  - `deploy/modal/app.py:712`, `:1148`, `:1167`, plus metadata writers around `:882`
- **What happens**  
  Default CLI invocations still use `configs/modal/smoke.yaml` and `configs/modal/train.yaml`. Those files were deleted, so:
  - `modal run --detach deploy/modal/app.py --action train` (accepting the default) now passes a path that does not exist.
  - The cache metadata block writes `"created": "/app/configs/modal/smoke.yaml"` / `"train.yaml"`, leaving an inaccurate SSOT for cache provenance.
- **Reproduce**
  ```bash
  python - <<'PY'
  from pathlib import Path
  print(Path('configs/modal/smoke.yaml').exists())
  print(Path('configs/modal/train.yaml').exists())
  PY
  # -> False / False
  ```
  Any Modal invocation that relies on the default (`--config` omitted) will hit `FileNotFoundError` when `train()` opens `cfg_abs` (`deploy/modal/app.py:819`).
- **Why it matters**  
  This is a straight regression: the simplest smoke command in every doc now crashes before launch, and cache metadata continues to cite paths we no longer ship.
- **Likely fix (not applied)**  
  Point defaults and metadata at `smoke_bimamba.yaml` / `train_bimamba.yaml` (and optionally surface FLA variants via explicit flags).

## P1 — Docker Image CMD Targets Nonexistent Config

- **Where**
  - `Dockerfile:143`
- **What happens**  
  The final CMD runs `python3.11 -m src train /app/configs/local/train.yaml`. After the split that file is gone, so a container started without overrides exits immediately with `FileNotFoundError`.
- **Reproduce**
  ```bash
  ls configs/local
  # -> smoke_bimamba.yaml  smoke_fla.yaml  train_bimamba.yaml  train_fla.yaml
  ```
  No `train.yaml` means the baked‑in CMD cannot succeed.
- **Why it matters**  
  Anyone pulling the image and executing the default entrypoint hits a crash; also breaks automation that depends on the old CMD.
- **Likely fix (not applied)**  
  Update CMD to `... train /app/configs/local/train_bimamba.yaml` (or add a lightweight wrapper that selects the desired stack).

## P2 — Modal README & Metadata Still Instruct Old Paths

- **Where**
  - `deploy/modal/README.md:49-63`
  - Cache metadata writer in `deploy/modal/app.py:886-926`
- **What happens**  
  The quick commands and metadata text still reference `configs/modal/smoke.yaml` / `train.yaml`. Following current docs leads straight to the P0 above; metadata remains misleading even after we fix the defaults.
- **Why it matters**  
  On-boarding docs are our SSOT; leaving stale paths here magnifies the Modal failure and undermines the CRAV audit trail.
- **Likely fix (not applied)**  
  Rewrite the README snippets and metadata strings once new defaults are in place.

## P2 — Flash-Linear Docs Claim Completed Phases + Config Paths That No Longer Exist

- **Where**
  - `docs/flash-linear-attention/FLA_DOCUMENTATION_METHODOLOGY.md:3-15`
  - `FLASH_LINEAR_ATTENTION_DOC2_NODE_MIGRATION.md`, Doc3, Doc4 (numerous references to `configs/local/phase1b_node_gdn.yaml`, etc.)
- **What happens**  
  The doc set still proclaims Phase 1b/2 COMPLETE with evidence files that were deleted. Anyone auditing the plan is told everything is green, then hits missing configs/logs immediately.
- **Why it matters**  
  CRAV status is now inaccurate; this is the same class of drift we promised to avoid. We need to restate “Phase 1b smoke in progress” and align instructions with the new `_bimamba`/`_fla` configs.
- **Likely fix (not applied)**  
  Rework the docs after we capture fresh smoke evidence, pointing at `smoke_fla.yaml` etc., and marking the remaining validation gates honestly.
